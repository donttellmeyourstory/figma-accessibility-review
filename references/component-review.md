# Проверка компонента

Сначала выясни назначение и применимые состояния. Не каждому компоненту нужны все состояния из примера.

| Состояние | Узел / источник спецификации | Контраст и различимость | Подпись / состояние | Неизвестные сведения |
|---|---|---|---|---|
| Обычное | | | | |
| Фокус | | | | |
| Наведение / нажатие | | | | |
| Выбор / раскрытие | | | | |
| Ошибка / ожидание | | | | |
| Неактивное | | | | |

Добавь доступные темы и размеры. Если вариант находится в библиотеке, а не в выбранном экране, запроси его через доступный инструмент или укажи пробел в охвате. Отсутствие варианта в выгрузке не доказывает отсутствие поведения в продукте.

Разделяй базовый компонент и локальные изменения экземпляра только при наличии соответствующих данных. Повторы общей причины объединяй в одно замечание со списком затронутых состояний.
