# Измерения и исключения

Для веба базовый ориентир — применимые критерии WCAG 2.2 A/AA. Нативные платформы требуют отдельного контекста: Figma px, CSS px, pt и dp нельзя автоматически считать одной единицей.

## Контраст

Получай фактические цвета текста и фона, включая прозрачность заливок и предков. Для градиентов, изображений и наложений оцени область под содержимым; одна выбранная точка не доказывает достаточность всей области. Если восстановление итоговых цветов ненадёжно, обозначь ограничение.

Сначала установи, что действительно отображается: выключенная заливка не участвует в композиции, а соседний слой может закрывать текст или менять его фон. Ближайший фон предка — только гипотеза, пока не проверены наложения. Полностью обрезанный или перекрытый текст не выдавай за видимый дефект; содержимое, доступное прокруткой, продолжай учитывать.

У градиента проверь фон в области букв либо надёжную границу контраста для всей этой области. Один плохой стоп с неизвестным положением относительно букв не подтверждает дефект. Хорошие крайние стопы также не гарантируют подходящую интерполяцию. Не определяй цвет текста по сглаженным краям глифов. Предлагаемый цвет исправления пересчитай на затронутых фонах и темах; без такого расчёта это только направление исправления.

Выполняй расчёт инструментом, а не приблизительной арифметикой модели. Для непрозрачного sRGB нормируй каналы в диапазон 0–1. Линеаризация: c/12.92 при c≤0.04045, иначе ((c+0.055)/1.055)^2.4. Яркость L=0.2126R+0.7152G+0.0722B. Отношение: (Lmax+0.05)/(Lmin+0.05). При прозрачности сначала восстанови итоговую композицию. Другие цветовые пространства требуют корректного преобразования.

Обычный текст: 4,5:1. Крупный: 3:1, когда подтверждены размер не менее 18 pt (24 CSS px) либо 14 pt (18⅔ CSS px) и жирное начертание. Не округляй значение вверх перед сравнением с порогом. Значимые графические признаки контролов и состояний оценивай по 1.4.11, обычно 3:1 к соседнему цвету.

Проверяй применимость исключений: неактивное управление, логотипы, декоративный или случайный текст и другие условия соответствующего критерия. Нельзя назначать обязательный минимум disabled-элементам без основания. Placeholder и доступное только для чтения содержимое не становятся неактивными автоматически. Декоративная линия не обязательно является значимым графическим объектом.

Источники: [1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).

## Цвет

Установи, какую информацию несёт цвет, и проверь наличие достаточного другого признака. Это может быть текст, форма, символ или иной доступный способ различения. Не предписывай иконку при уже достаточной подписи. Причина ошибки должна быть понятна и связана с полем.

Если дополнительный признак — светлотная разница, подтверди не менее 3:1 между сравниваемыми цветами и понятность их смысла в контексте. Небольшое изменение яркости или один оттенок не дают такого доказательства.

Источник: [1.4.1](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html).

## Цели указателя

Критерий 2.5.8 AA предусматривает 24×24 CSS px либо исключение. 44×44 CSS px относится к усиленному критерию 2.5.5 AAA. Оценивай интерактивную область, подтверждённую спецификацией, а не только видимую иконку.

Для малой цели проверь исключения:

- Расстояние: круг диаметром 24 CSS px вокруг центра малой цели не пересекает другую цель или аналогичный круг другой малой цели.
- Эквивалент: то же действие имеется на этой странице через соответствующую цель.
- Встроенность в строку: цель находится в предложении либо ограничена высотой строки окружающего текста.
- Настройка браузера: размер определён пользовательским агентом и не изменён автором.
- Существенность: именно такое представление необходимо для информации или требуется законом.

Зафиксируй масштаб, геометрию и основание исключения. Неизвестная область соседнего управления не позволяет уверенно подтвердить расстояние.

Источники: [2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html), [2.5.5](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html).

## Смысл и адаптация

Постоянные подписи и инструкции должны объяснять ввод; подсказка placeholder не заменяет все необходимые подписи. При наличии спецификации доступного имени сравни его с видимым текстом. Tooltip сам по себе не подтверждает программное имя.

Определи назначение изображения до предложения альтернативы. Для графика нужна его существенная информация, для функциональной картинки — назначение действия, для декора отдельная озвучка обычно не требуется. Не выдумывай содержимое по имени слоя.

Подпись «Изображение 2» сама по себе не передаёт данные графика, но не доказывает дефект: полноценный эквивалент может быть в соседнем тексте, таблице или связанном описании. Когда другие альтернативы неизвестны, задай вопрос об их достаточности. Подтверждай проектный пробел лишь при полном контексте или явном указании, что подходящего эквивалента нет. Сгенерированные по макету React/HTML и их alt/ARIA не являются доказательством устройства настоящего продукта.

Смысловой порядок и заголовки описывай как проектные требования. Не выводи порядок чтения из списка слоёв. Проверяй решения для длинных подписей, увеличения текста, узкого экрана и ошибок, но отсутствие соответствующего фрейма отмечай как пробел в доступной документации.

Источники: [2.5.3](https://www.w3.org/WAI/WCAG22/Understanding/label-in-name.html), [1.1.1](https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html), [3.3.2](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html).

## Формы и взаимодействие

Для применимых финансовых, юридических операций и изменения пользовательских данных предусмотрен хотя бы один механизм: обратимость, проверка ввода с исправлением либо просмотр и подтверждение. Не требуй дополнительный экран, если работает другой допустимый механизм. Источник: [3.3.4](https://www.w3.org/WAI/WCAG22/Understanding/error-prevention-legal-financial-data.html).

В одном процессе повторно запрашиваемые сведения, ранее введённые или предоставленные пользователю, должны автоподставляться или быть доступны для выбора. Исключения: повтор существенен, нужен для безопасности или данные утратили актуальность. Источник: [3.3.7](https://www.w3.org/WAI/WCAG22/Understanding/redundant-entry.html).

При аутентификации проверь альтернативу когнитивному тесту или механизм помощи — например, менеджер паролей и вставку. Критерий допускает исключения для распознавания объектов и личного контента; любая CAPTCHA не является автоматически нарушением. Макет подтверждает только предусмотренное решение, работу проверяют на стенде. Источник: [3.3.8](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html).

Для дополнительного содержимого, появляющегося при hover/focus, нужны закрываемость, возможность навести на само содержимое и сохранение до ухода, закрытия или утраты актуальности. Учитывай исключения критерия, включая условия, когда оно не перекрывает контент или сообщает об ошибке ввода. Поведение, которого нет в выгрузке, передавай в QA как вопрос. Источник: [1.4.13](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html).
