# Участие в разработке

Спасибо за интерес к Figma Accessibility Review. Особенно полезны исправления неоднозначных правил, примеры ложных срабатываний и улучшения отчётов.

## Подготовка

Сделайте fork и клонируйте свою копию. Это Markdown-скилл без программных зависимостей, сервера и сборки. Прочитайте [SKILL.md](SKILL.md) и связанный с изменением справочник в `references/`.

## Изменения

Создайте отдельную ветку, внесите небольшое связное изменение и откройте pull request. В описании укажите проблему, новое поведение и способ проверки. Если изменяется критерий доступности, приложите ссылку на первичный открытый источник и проверьте применимые исключения.

Пишите понятным языком. Сохраняйте разделение между измеримыми проблемами макета, неопределённостью, рекомендациями и тестами готового интерфейса. Не называйте отсутствие спецификации доказательством ошибки реализации.

## Проверка перед pull request

- Проверьте относительные ссылки и соответствие инструкции связанным справочникам.
- Для изменения поведения пройдите релевантный пример с ожидаемым и фактическим результатом; не заявляйте о проверке, которую не проводили.
- Убедитесь, что отчёт не обещает соответствие всего продукта WCAG по одному макету.
- Используйте только примеры, которые разрешено публиковать. Не добавляйте токены, персональные данные или закрытые материалы.

## Сообщение о проблеме

В issue опишите запрос к агенту, использованную среду, доступный тип данных, ожидаемый и фактический результат. По возможности приложите минимальный публичный пример. Для вопросов по критериям укажите проверяемый элемент, платформу, тему, масштаб и основание вывода.

## Using Codex

Откройте репозиторий в Codex и попросите внести конкретное изменение. [AGENTS.md](AGENTS.md) даёт контекст проекта. Проверьте результат и источники самостоятельно: сгенерированное объяснение не заменяет проверку критерия и примера.

Вклад в репозиторий предоставляется на условиях [MIT](LICENSE). Права на внешние источники остаются у их правообладателей.
